Cloudflare Pages에 기술블로그를 올리기까지

Astro 정적 빌드부터 Pages 배포, 공개 URL 검증까지의 실제 절차를 정리했습니다.

#cloudflare-pages#astro#hosting

왜 Cloudflare Pages인가

기술블로그의 요구사항은 단순합니다. 빠르고, 싸고, 깨져도 바로 되돌릴 수 있을 것.

  • 정적 파일이면 충분하다 — SSR이 필요 없는 콘텐츠다
  • 엣지 캐시가 기본이다 — 별도 CDN 설정이 필요 없다
  • 배포마다 고유 URL + 히스토리가 남는다 — 롤백이 버튼 하나다

그래서 Next.js 풀스택 대신 Astro 정적 출력 + Pages를 골랐습니다.

빌드 구조

src/content/posts/*.md  →  Astro Content Collections
src/pages/blog/index.astro →  글 목록
src/pages/blog/[...slug].astro →  글 상세
dist/                    →  Cloudflare Pages에 업로드되는 정적 산출물

핵심은 dist/만 있으면 호스팅이 된다는 점입니다. 프레임워크에 종속된 런타임이 없습니다.

배포 명령

npm run build
npx wrangler pages deploy dist --project-name=bungae-tech-blog

처음엔 프로젝트가 자동 생성되고, 두 번째부터는 같은 프로젝트에 새 배포가 쌓입니다. 문제가 생기면 대시보드 Deployments에서 이전 버전을 Rollback하면 끝입니다.

검증 체크리스트

  1. *.pages.dev 공개 URL이 200으로 응답하는가
  2. /blog/에서 글 목록이 렌더링되는가
  3. /blog/... 상세 페이지가 열리는가
  4. 콘솔 에러 없이 정적 에셋이 로드되는가

다음 단계는 blog.bungae.site 커스텀 도메인 연결입니다. 이번 배포에서는 범위 제외입니다.
