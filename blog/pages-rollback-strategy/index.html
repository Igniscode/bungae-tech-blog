정적 블로그 롤백 전략: Pages Deployments

깨진 배포가 나가도 1분 안에 되돌리는 Pages 히스토리 기반 롤백 절차.

#cloudflare-pages#ops#rollback

배포는 쌓이고, 롤백은 가리킨다

Cloudflare Pages의 배포 모델은 단순합니다.

  1. 매 배포는 불변(immutable) 스냅샷이다
  2. 프로덕션 트래픽은 특정 배포를 가리킨다
  3. 롤백 = 포인터를 이전 배포로 옮기는 것이다

절차

  1. Cloudflare 대시보드 → Pages → 프로젝트 → Deployments
  2. 되돌릴 배포 → ··· → Rollback to this deployment
  3. 공개 URL에서 이전 HTML이 서빙되는지 확인

API로도 가능합니다.

# 배포 목록
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT/pages/projects/$PROJECT/deployments"

이 블로그의 약속

  • dist/는 로컬에서 재현 가능 (npm run build)
  • 깨진 배포는 삭제하지 않고 히스토리에 남긴다 (원인 추적용)
  • 커스텀 도메인은 롤백 포인터를 따라가므로, 도메인 재설정이 필요 없다

단순한 것이 고장날 때 가장 빠르게 고쳐진다.
